# Bulk Forge Management

**Status**: Implemented
**Date**: 2026-01-17

## Summary

Added commands for bulk management of forge assignments across repos, plus simplified sync workflow.

## New Commands

### `repos add_forge`

Adds a forge to all repos that don't already have it.

```bash
synapse plexus hyperforge org hypermemetic repos add_forge --forge github
```

**Output:**
```yaml
operation: add-forge github
repos_updated: [claude-container]
repos_skipped: [substrate, synapse, hub-core, ...]
```

### `repos set_default_forges`

Sets organization-level default forges for inheritance.

```bash
synapse plexus hyperforge org hypermemetic repos set_default_forges --forges github,codeberg
```

**Result in repos.yaml:**
```yaml
owner: hypermemetic
default_forges:
- github
- codeberg
repos:
  new-repo:
    # forges: omitted - inherits [github, codeberg]
    visibility: public
```

### `repos sync`

Sync repos without specifying workspace path (looks up from org bindings).

```bash
# Preview (dry-run)
synapse plexus hyperforge org hypermemetic repos sync

# Apply changes
synapse plexus hyperforge org hypermemetic repos sync --yes
```

### Inheritance Behavior

When a repo config has `forges: None` (omitted), `ReposConfig::effective_forges()` returns:
1. The repo's explicit `forges` if set
2. Otherwise, `default_forges` from the org
3. Otherwise, empty vec

## What Happens to Git Remotes When Forges Change?

**Short answer: Nothing automatic.**

### Current Behavior

1. **Forge sync** (`repos sync`) manages repos on remote forges (GitHub/Codeberg APIs)
   - Creates/updates/deletes repositories on the forge
   - Updates synced state tracking

2. **Git remotes** are managed separately via `GitRemoteBridge`
   - Called during `clone` operations
   - Called when viewing repo details (validates/adds missing remotes)
   - NOT automatically called when forge config changes

### Gap Identified

When you add a forge to a repo's config (e.g., add `github` to a repo that only had `codeberg`):

1. ✅ `repos sync` creates the repo on GitHub
2. ❌ Local git repo doesn't automatically get a `github` remote added

**Workaround:** Navigate to the repo and run:
```bash
synapse plexus hyperforge org hypermemetic repos <repo_name> show
# This triggers remote validation and adds missing remotes
```

Or manually:
```bash
git remote add github git@github-hypermemetic:hypermemetic/<repo>.git
```

### Potential Enhancement

Could add a `repos sync_remotes` command that:
1. Scans workspace for git repos
2. For each repo in config, ensures git remotes match configured forges
3. Adds missing remotes, optionally removes stale ones
